Spring Boot와 H2(메모리 DB) 조합으로 가장 단순하게 만드는 방법을 알려드릴게요. 금융권에서 Java/Spring을 많이 쓰고, H2는 설치 없이 바로 돌아가서 단기간 프로젝트에 적합합니다. Python이 더 편하시면 같은 구조를 FastAPI + SQLAlchemy로 옮겨도 됩니다.

## 1. 프로젝트 설정

[start.spring.io](https://start.spring.io)에서 아래 의존성을 선택해 생성합니다.
- Spring Web, Spring Data JPA, H2 Database, Lombok, Validation

## 2. 기능 범위 (이 정도면 충분합니다)

- 계좌 개설 `POST /accounts`
- 입금 `POST /accounts/{id}/deposit`
- 출금 `POST /accounts/{id}/withdraw`
- 이체 `POST /transfers`
- 거래내역 조회 `GET /accounts/{id}/transactions`

## 3. 테이블 설계

**Account**: `id`, `accountNumber`(unique), `balance`(long, 원 단위), `createdAt`

**TransactionHistory**: `id`, `fromAccountId`, `toAccountId`, `amount`, `type`(DEPOSIT/WITHDRAW/TRANSFER), `idempotencyKey`(unique), `createdAt`

잔액은 `long`(원 단위)으로 두면 소수점 오차 걱정이 없습니다. 이자 계산처럼 소수가 필요해지면 그때 `BigDecimal`을 쓰세요.

## 4. 핵심 코드

**Account 엔티티: 잔액 검증을 엔티티 안에 둡니다**
```java
@Entity
@Getter
@NoArgsConstructor
public class Account {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String accountNumber;
    private long balance;

    public void deposit(long amount) {
        if (amount <= 0) throw new IllegalArgumentException("금액은 0보다 커야 합니다.");
        this.balance += amount;
    }

    public void withdraw(long amount) {
        if (amount <= 0) throw new IllegalArgumentException("금액은 0보다 커야 합니다.");
        if (this.balance < amount) throw new IllegalStateException("잔액이 부족합니다.");
        this.balance -= amount;
    }
}
```

**Repository: 비관적 락으로 조회**
```java
public interface AccountRepository extends JpaRepository<Account, Long> {
    @Lock(LockModeType.PESSIMISTIC_WRITE)
    @Query("select a from Account a where a.id = :id")
    Optional<Account> findByIdForUpdate(@Param("id") Long id);
}
```

**이체 서비스: 가장 중요한 부분**
```java
@Service
@RequiredArgsConstructor
public class TransferService {
    private final AccountRepository accountRepository;
    private final TransactionHistoryRepository historyRepository;

    @Transactional
    public void transfer(Long fromId, Long toId, long amount, String idempotencyKey) {
        // 1. 멱등성: 이미 처리된 요청이면 그냥 종료
        if (historyRepository.existsByIdempotencyKey(idempotencyKey)) return;

        if (fromId.equals(toId)) throw new IllegalArgumentException("같은 계좌로 이체할 수 없습니다.");

        // 2. 데드락 방지: 항상 id가 작은 계좌부터 락을 잡음
        Long firstId = Math.min(fromId, toId);
        Long secondId = Math.max(fromId, toId);
        Account first = accountRepository.findByIdForUpdate(firstId).orElseThrow();
        Account second = accountRepository.findByIdForUpdate(secondId).orElseThrow();

        Account from = fromId.equals(firstId) ? first : second;
        Account to = fromId.equals(firstId) ? second : first;

        // 3. 출금 + 입금 (예외가 나면 @Transactional이 전체 롤백)
        from.withdraw(amount);
        to.deposit(amount);

        historyRepository.save(TransactionHistory.transfer(fromId, toId, amount, idempotencyKey));
    }
}
```

## 5. 면접에서 말할 수 있는 3가지 포인트

| 문제 | 해결 방법 |
|------|----------|
| 이체 중 오류 발생 시 돈이 사라지는 문제 | `@Transactional`로 출금·입금을 하나의 트랜잭션으로 묶어 롤백 |
| 동시 출금 시 잔액이 꼬이는 문제 | 비관적 락(`SELECT ... FOR UPDATE`) |
| A→B, B→A 동시 이체 시 데드락 | 락을 항상 id 순서대로 획득 |
| 네트워크 재시도로 중복 이체되는 문제 | 멱등성 키(unique 컬럼)로 중복 요청 차단 |

## 6. 동시성 테스트 (포트폴리오의 핵심 증거)

```java
@Test
void 동시에_100번_출금해도_잔액이_정확하다() throws Exception {
    Long id = createAccountWithBalance(100_000);
    int threads = 100;
    ExecutorService pool = Executors.newFixedThreadPool(32);
    CountDownLatch latch = new CountDownLatch(threads);

    for (int i = 0; i < threads; i++) {
        pool.submit(() -> {
            try { accountService.withdraw(id, 1_000); }
            finally { latch.countDown(); }
        });
    }
    latch.await();

    assertEquals(0, accountRepository.findById(id).orElseThrow().getBalance());
}
```

락이 없을 때 이 테스트가 실패하는 모습을 먼저 보여주고, 락을 적용해서 통과시키는 과정을 README에 적으면 설득력이 확 올라갑니다.
